# 批量歌词缓存提速

`0.8.5.2-preview.6` · Android `versionCode 138` · 本地 ARM64 测试版，未发布 Release。

## 原因与修改

原处理器逐首等待完整网络链路，歌词来源为“本地优先”时，服务器无词的歌曲还会继续等待 LRCLIB。外部来源连续失败也可能触发整个任务的停止门禁。实机排查观察到服务器正常返回空歌词、外部服务返回 HTTP 503 的情况；单次诊断不替代旧请求未保存的异常记录，也不能解释所有历史失败。

新版仅对歌词启用最多 3 条并行通道，同一任务在内存中去重，结果由一个协调器逐项落库、统计。慢请求不会阻塞另外两条通道，艺人和专辑封面仍串行，共享网络配额保留。缓存查询和完整歌词写入由批量调用方统一执行，消除原来两层的重复读写。

只有主服务器已成功回答且确实无词后，外部回退异常才作为独立的单项失败保留，不再触发主服务器故障的连续失败停止门禁。认证、主服务器网络和磁盘等普通错误仍受连续 3 次失败门禁保护。不改变歌词来源，不将网络故障标为“来源未提供”，不自动重试整个库。

暂停、离线、仅 Wi-Fi、账号变化或失败门禁停止时，关闭处理器拥有的请求上下文；未完成项目保留为待处理，迟到响应不能写入新的歌词缓存。LRCLIB 目录准备完成后也再次检查归属，避免在暂停期间创建目录后继续写入歌词文件。原任务通过“继续”或“仅重试失败项目”承接，不重新扫描，不清除现有缓存、登录或离线音频。

## 验证

针对实际协调器验证 3 通道去重、慢首项下后续推进、串行提交、封面串行、及时暂停、网络及账号变化、迟到响应、普通失败预算、外部回退失败隔离。数据层验证只读一次、只写一次并完整保留逐词对象；LRCLIB 缓存测试验证暂停期间的目录等待和增强 LRC 的原始字词计时。

1113 项完整测试、类型与翻译检查、变更代码 lint、diff 检查通过。ARM64 原生构建通过，15 个变更的产品源码与实际 Hermes 包逐字核验。安装包为 `artifacts/Resonus-Glass-v0.8.5.2-preview.6-code138-arm64-v8a.apk`，45,790,516 bytes，SHA-256 为 `7f68539c87e3ede8556ccf28f886578448ba02f22a75a96694f226a7fa6fa791`，沿用原包名及签名。

三星已覆盖安装 138，原登录、任务游标、来源和选择项保留；既有离线音频保持，抽查的已有歌词内容及结构在安装前后一致。

沿原队列重试后，成功、已有缓存、来源未提供和失败分别统计，失败保持独立可重试，未清除或改成“来源未提供”。本次观察不代表全库缓存已完成；旧条目未保存原始异常，不能断言每个失败项都是同一外部故障。

实机暂停后的观察窗口内，任务结果及歌词缓存内容保持不变，后台保护服务退出；点击“继续”承接原进度。切到系统桌面后仍能处理任务并保存新歌词，原生 UIDT 和 headless 保护有效。速度随歌曲和外部服务状态变化，不承诺全程固定速度或固定倍数。

抽查新保存的正缓存均为合法、非空歌词，有逐词信息的记录保留原计时，未发现时间结构错误。测试辅助组件及临时设置已清理或恢复。详细现场诊断与收据不进入公开仓库；本次预览完成时未发布 Release 或推送源码。
