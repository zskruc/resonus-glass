# Android DNS recovery

This module handles a resolver mismatch observed on the Samsung with Clash disabled: `InetAddress.getAllByName` and `Network.getAllByName` failed with `UnknownHostException`, while an explicit system AAAA query on the same active network returned the NAS's current IPv6 address. This identifies the failing lookup path; it does not establish the underlying Android or router defect.

`withNetworkRecovery` installs the React Native OkHttp factory immediately after `MainApplication.onCreate` calls `super`, before React Native loads. Each client retains its default builder, separate cookie container, dispatcher and connection pool. One cache owns the original context-based disk-cache directory. The audio and file-system patches inherit only the DNS implementation and preserve their original cookie, cache, timeout, local-URI and resumable-download behavior.

System DNS remains the first choice. Only `UnknownHostException` enables the Android 29+ fallback. It queries AAAA through `DnsResolver` on the calling UID's current default network, including an active VPN, accepts only successful nonempty IPv6 answers, and preserves the original hostname and HTTPS certificate checks. No fixed IP, external DNS service or process/socket network binding is used. The fallback has a three-second budget, deduplicates simultaneous queries by hostname and network handle, cancels when that network changes, and retries once within the original budget. There is no additional persistent address or failure cache. The initial system lookup retains the system's own timeout.

Seven JVM tests cover the system fast path, failure types, unsupported/unavailable paths, IPv6 answer validation, failure cleanup, network changes and concurrent-query deduplication. The complete app also passes its 170 existing tests and canonical-ID checks, TypeScript and focused lint, and builds as an ARM64 release.

On 2026-10-07, the opt-in QA build returned HTTP 200 through React Native XHR, Expo fetch and the legacy file-system download client on the Samsung with Clash disabled. The download transferred the 190-byte unauthenticated ping response and deleted its own temporary file. This proves the download transport, rather than a complete offline-song download. The user confirmed that the signed-in Home screen loaded. Native media-session diagnostics showed a buffered track with no playback error. Sound was separately routed to the mirror's `remote_submix` channel at volume zero; closing the mirror restored the phone speaker and its prior volume. Audible playback confirmation is pending.

All temporary transport/DNS probe source has been removed. The normal APK contains no probe symbols, and installs over the existing preview without clearing data.
